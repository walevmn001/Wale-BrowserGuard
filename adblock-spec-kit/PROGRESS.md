## Dở dang / ghi chú cho phiên sau
- T016 xong: popup (`src/popup/`: `index.html` + `popup.ts` + helper thuần `url.ts`). Popup là view mỏng trên `Whitelist`/`StatsCounter`/`RulesetManager` (không cache state). Chức năng: hiện domain + trạng thái chặn của tab hiện tại (AC-2.1), tổng + theo tab (AC-3.1), nút "Xoá thống kê" (AC-3.2), nút tắt/bật toàn bộ (AC-2.3). Nhắm **tab active lúc mở** (`chrome.tabs.query({active,currentWindow})`, resolve 1 lần) — **không cần quyền `tabs`** (đọc `tab.url` nhờ host `<all_urls>`); `domainFromUrl` chỉ nhận http/https. Chuỗi tiếng Việt hard-code, **T017** lo i18n. Test: 2 unit (`tests/unit/url.test.ts`) + 1 e2e (`tests/e2e/popup.spec.ts`) phủ AC-2.1/2.3/3.1/3.2.
- **T016 đã sửa 2 bug concurrency do chính nó phơi ra** (đã stress e2e full-suite **20 lần liên tiếp xanh**):
  1. **Whitelist** — popup (`Whitelist.setEnabled` → `updateDynamicRules`) và service worker (`storage.onChanged` → `applyStored`) cùng `addRules` một id → Chrome báo `Rule with id … does not have a unique ID`. Sửa: **worker là nơi DUY NHẤT ghi dynamic rule**; `setEnabled` chỉ ghi `chrome.storage` (desired state); `applyStored` reconcile (xoá id thừa trong dải whitelist + upsert id mong muốn, 1 lệnh `updateDynamicRules`) → deps thêm `getDynamicRules`.
  2. **Stats** — `poll()` chồng nhau (2 lần `applyStoredState` lúc khởi động) đọc cùng cursor → đếm trùng (log `+2 (total 2)` rồi `+2 (total 4)`). Sửa: `poll()` xếp hàng qua 1 promise `pollQueue` (**module var duy nhất**, chỉ là điều phối tạm, không phải state người dùng); popup **chỉ đọc** snapshot, **không tự poll** → chỉ worker đếm (đổi quyết định "poll on-demand" nêu ở ghi chú T015).
  - Manifest: thêm `background.type: 'module'` (SW giờ là ES module vì import chunk chia sẻ với popup). E2E popup retry reload sau khi whitelist vì DNR lan truyền xuống network layer bất đồng bộ.
- T015 xong: `src/background/stats.ts` = đếm request đã chặn theo tab + tổng. **Cách đếm (đã tra tài liệu @types/chrome):** DNR không có bộ đếm cho static rule; API chính thức để biết rule nào khớp là `chrome.declarativeNetRequest.getMatchedRules(filter)` → cần quyền **`declarativeNetRequestFeedback`** (đã thêm vào manifest, plan §3). `StatsCounter` (inject `storage`/`getMatchedRules`): `poll()` đọc con trỏ `statsCursor` rồi gọi `getMatchedRules({minTimeStamp: cursor})`, cộng dồn vào `statsTotal` + `statsByTab`, cập nhật cursor = timestamp mới nhất (không đếm trùng); `snapshot()`, `forTab(tabId)`, `reset()` (xoá total+byTab, **giữ** cursor để không đếm lại). Key mới trong `StorageSchema`: `statsTotal`, `statsByTab`, `statsCursor`. `service-worker.ts` gọi `poll()` khi cài/khởi động + `chrome.tabs.onUpdated` (status `complete`) — **không cần quyền `tabs`** vì chỉ dùng `tabId`/`status`. Test: 5 unit (`tests/unit/stats.test.ts`) + e2e (`tests/e2e/stats.spec.ts`: 3 script quảng cáo → total = 3, đúng cả theo tab). **TODO(verify)/giới hạn API:** getMatchedRules chỉ trả match trong 5 phút gần nhất và gắn với document đang hoạt động, quota 20 lần/10 phút; cân nhắc `chrome.alarms` (P2) nếu cần poll nền. KHÔNG dùng `onRuleMatchedDebug` (chỉ chạy với extension unpacked).
- T014 xong: `src/background/whitelist.ts` = whitelist theo domain (thuật toán C). `Whitelist` (inject `storage`/`updateDynamicRules`), `whitelistRuleId(domain)` (hash FNV-1a ổn định → id trong dải riêng `WHITELIST_RULE_ID_BASE=1_000_000`, tránh đụng id ruleset tĩnh), `buildAllowAllRule(domain)` (`{priority: PRIORITY.WHITELIST_ALLOW_ALL=1000, action:{type:'allowAllRequests'}, condition:{requestDomains:[domain], resourceTypes:['main_frame','sub_frame']}}`), `createWhitelist()` (nối `chrome.*`). API: `list/isAllowed/setEnabled(domain, enabled)/applyStored`. **Idempotent**: thêm cùng domain nhiều lần → 1 entry + 1 rule; cập nhật bằng **1 lệnh `updateDynamicRules`** (remove+add cùng lúc). Danh sách domain ở `chrome.storage` key `whitelist` (đã thêm vào `StorageSchema`). `service-worker.ts` gọi `applyStored()` khi cài/khởi động + `chrome.storage.onChanged` key `whitelist`. Test: 10 unit (`tests/unit/whitelist.test.ts`, idempotent) + e2e (`tests/e2e/whitelist.spec.ts`: baseline chặn → set whitelist `localhost` → request qua; relaunch cùng userDataDir → list + dynamic rule còn). Lưu ý: `requestDomains` dùng domain ascii; e2e whitelist domain `localhost` (server bind mọi interface).
- T013 xong: `src/background/ruleset-manager.ts` = công tắc tổng. `RulesetManager` (inject `storage`/`ruleSetIds`/`updateEnabledRulesets`), `ruleSetIdsFromManifest()` (đọc id ruleset từ manifest), `createRulesetManager()` (nối `chrome.*`). Trạng thái ở `chrome.storage` key `enabled` (mặc định ON). `service-worker.ts` gọi `applyStored()` khi cài/khởi động + `chrome.storage.onChanged` → tắt/bật bằng `updateEnabledRulesets`. **Đã thêm quyền `storage` vào manifest** (plan §3, P1) — thiếu nó thì `chrome.storage` undefined trong SW. E2E `tests/e2e/master-switch.spec.ts`: set `enabled=false` qua SW → `getEnabledRulesets()` rỗng → request quảng cáo không còn `ERR_BLOCKED_BY_CLIENT`.
- T012 xong: static rulesets được khai báo trong `manifest.config.ts` (`declarative_net_request.rule_resources`, permissions `declarativeNetRequest` + `storage`, host `<all_urls>`) + `scripts/static-rulesets.ts` (descriptor: id/category/source/output) + `scripts/build-rulesets.ts` (đọc `rules/source/*.txt` → converter T010 → validate T011 → JSON). Vite plugin `adblock-emit-rules` emit `dist/rules/static/*.json`. E2E `tests/e2e/block-ad-script.spec.ts`: script từ `ads.example.test` bị chặn `ERR_BLOCKED_BY_CLIENT`, script cùng origin vẫn chạy. Chạy e2e bằng `xvfb-run -a npm run test:e2e` (cần `npm run build` trước).

- T010 xong: `scripts/build-rules.ts` = converter ABP→DNR tối giản (thuần, không CLI). API: `convertFilterList(lines, category, startId)`, `groupByCategory`, `summarize`. Ngoài tập đó → bỏ có kiểm soát + ghi báo cáo (`SkipReason`). Priority lấy từ `PRIORITY` (block=500, exception=800, malware=900). File 294 dòng (sát trần 300): nếu cần thêm code, TÁCH module con.
